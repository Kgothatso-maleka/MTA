## Scenario

Khanyisa Solar's sales reps find the Opportunity page crowded. Installers need a simple page for Installations, the service desk wants to work many cases at once, and managers want a home page with their numbers.

## Your goal

Design three focused experiences with Lightning App Builder.

## Before you start

- A Developer Edition org or Trailhead Playground.
- The Installation object and a few sample records.

## What to build

1. A Lightning app **Sales** with standard navigation, and an app **Service Desk** with **console navigation** and a utility bar with Recent Items.
2. A **record page** for Installation with tabs for Details and Related, using **Dynamic Forms** so the Commercial section shows only when Customer Type is Commercial.
3. A **home page** with a dashboard component, assigned to the Sales app for the Sales Manager profile.
4. A **compact layout** for Installation that shows Status and System Size in the highlights panel.
5. A **quick action** to log a call and a **global action** to create a task.
6. A **Path** for Installation (Planned, In Progress, Completed) with key fields and guidance.
7. A **list view** "My Open Installations" shared with a public group.

## What you should see when you are done

- [ ] Different users get different pages, home pages and apps.
- [ ] The Commercial section appears and disappears with the picklist.
- [ ] The Path shows guidance when you click each stage.
- [ ] You can explain which tool you used for each need and why.

## Check your understanding

- [ ] What is the difference between a page layout and a Lightning record page?
- [ ] Where would you hide a field **security-wise**: layout or field-level security?
- [ ] When does console navigation make sense?

## Stretch goal

Add a component visibility filter that shows a warning banner only when an Installation is past its planned date.
